# Relay-Box (PR 1 von 5) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Der Relay bekommt ein zweites Durable Object `Box`: eine WebSocket-Mailbox mit zwei ersetzbaren Slots (`req`: Handy → Desktop, `res`: Desktop → Handy), die opake Bytes speichert und dem Gegenüber zustellt.

**Architecture:** Beide Seiten halten eine WebSocket (Hibernation API) zum selben DO, benannt nach `sha256(Geheimnis)`. Der Worker prüft nur Origin, Rate-Limit und Geheimnis (im Subprotocol) und reicht den Upgrade durch; das DO speichert Bytes, zählt je Slot eine Version hoch und stellt zu. Kein JSON, keine Kryptografie im Worker. `Device` (Push) bleibt unberührt.

**Tech Stack:** Cloudflare Workers + Durable Objects (SQLite), reines JavaScript ohne Build, `node --test`, `wrangler` 4.153.0.

**Spec:** `docs/superpowers/specs/2026-11-02-ios-relay-abgleich-design.md` (Abschnitte „Budget“, „Relay-Schnittstelle“, „Tests“). Issue #358, alle Commits/PR mit `Refs #358`.

## Global Constraints

- **Kein Logging** von Geheimnis, Subprotocol, URL-Query, Nachrichteninhalt — auch nicht in Fehlerpfaden (`relay/CLAUDE.md`, Regel).
- **Kein `Buffer`** im Laufzeitcode (nur in Tests); Bytes als `Uint8Array`/`ArrayBuffer`.
- **Kein `JSON.parse`/`JSON.stringify` auf Nutzbytes**, keine Krypto im Worker (10 ms CPU, Workers Free).
- `LIMITS.maxFrame` = `1_048_576` Bytes je Nachricht; Geheimnis = 43 Zeichen Base64url (`parseSecret`-Format); Subprotocol `zeit.v1`.
- Nachrichtentypen: `0x01 put` (Client→Relay), `0x02 slot` (Relay→Gegenüber, `ver` 4 Byte big-endian + Nutzbytes), `0x03 ok` (Relay→Absender, `ver` 4 Byte big-endian).
- Je Rolle (`phone`, `desktop`) höchstens eine Verbindung; die neue ersetzt die alte (Schließcode 1000).
- Schreibvorgänge sparsam (Free: 100 000 Zeilen/Tag): ein `put` = **ein** Speicherschreibvorgang für den Slot; der Selbstreinigungs-Alarm wird höchstens einmal am Tag neu gesetzt.
- Selbstreinigung nach `LIMITS.idleDays` (90) ohne `put`; Konstanten bleiben in `validate.js`.
- **Datenschutz** (Spec, Abschnitt „Datenschutz“): `Box`-Objekte nur über `env.BOX.jurisdiction('eu')` ansprechen (nie `env.BOX.idFromName` direkt — später nicht nachziehbar); `[observability] enabled = false` in `wrangler.toml`; Datenflüsse und Fristen gehören nach `docs/datenschutz.md`.
- Tests: `npm test` in `relay/` (Node ≥ 22). Neue Dateien tragen das Kopf-Kommentarmuster der bestehenden (`// relay/...`, deutsch).
- Shell-Befehle für den Nutzer ohne `&&` (PowerShell 5.1): mit `;` trennen.

## Review Focus

1. **Gegenüber offline:** `put` ohne verbundenes Gegenüber speichert, quittiert (`ok`) und liefert beim nächsten Verbinden aus (Task 3).
2. **Wiederaufnahme:** Verbinden mit `have >= ver` liefert nichts erneut aus; `have` ungültig (negativ, Text, > 2³¹) → `400` (Task 1, 3).
3. **Übergroße Nachricht:** `maxFrame + 1` Bytes schließt mit 1009 und schreibt **nichts** in den Speicher; Textnachricht schließt mit 1003 (Task 3).
4. **Geheimnis-Hygiene:** Antwort-Subprotocol ist genau `zeit.v1`, das Geheimnis taucht in keiner Antwort, keinem Header zum DO und keinem `console.*`-Aufruf auf (Task 4).
5. **Doppelte Verbindung / Löschen:** zweite Desktop-Verbindung schließt die erste, Slots bleiben; `DELETE /v1/box` löscht Slots, Alarm und schließt alle Sockets (Task 3, 4).
